# ADR-048: 剧本视频工作台

## Status
Accepted — 用户明确要求按阶段实现工作台、持久化关联、异步生成及导出。

## Decision
新增 production 应用模块，管理剧本快照、版本化分镜文档、待确认规划、生成历史与导出关联。场景和镜头为有稳定 UUID 的受限 JSONB 文档（最多100镜头），统一乐观版本；媒体引用使用显式关联表。原剧情 Scene 与制作 Scene 用途不同，前者写作，后者是不可静默同步的制作快照。

复用 Storyline/Characters Service 获取快照；复用 TextCompletionService 与文本 Worker 解析结构化分镜；建议经人工编辑确认写入。图片/视频生成复用现有 Generation Service、模型能力目录及 Worker；任务和镜头关联同事务。失败重试创建新版本，旧成功结果保持。原始资源删除检查制作引用。

复用 EditorService 生成不可变导出工程，复用 editor Worker 的 FFmpeg 统一编码、尺寸、帧率及音频。不新增队列、供应商或前端依赖。PG 真值；不使用 Redis/Celery result 保存制作数据。

现有适配器只开放已接通的文生视频及单首帧视频；不声称尾帧、多角色参考或锁定身份可用。参数接口取当前配置与适配器能力交集；不允许 UI 猜测模型能力。人物参考在生成前由授权服务读取，制作保存源引用及当次身份文本快照。

## Implementation phases
1. 复用点与契约分析。
2. 数据模型、迁移、版本化 CRUD 与项目隔离。
3. 异步分镜建议及人工确认。
4. 角色/资产参考与分镜图。
5. 视频提交与能力约束。
6. 历史、采用版本、真实任务状态。
7. 轻量时间线与异步 MP4 导出。

每阶段验证对应风险；外部供应商未实际调用时不声称真实成片验收通过。
